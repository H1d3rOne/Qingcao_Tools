# 咸鱼监控页命中商品折叠预览设计

## 背景

当前 `web-vue/src/views/xianyu/components/XianyuMonitorPanel.vue` 在右侧详情区会直接展示当前任务的全部“最近命中”商品。任务命中较多时，页面会被商品卡片迅速拉长，导致：

- 任务基础信息被命中商品列表淹没
- 页面初始浏览负担偏重
- 左侧任务切换时，右侧视觉重心不够集中

同时，左侧任务列表中任务标题与其他信息层级接近，当前任务名称不够突出，扫描效率一般。

## 目标

1. 右侧“最近命中”区域默认不直接展开全部商品
2. 提供明确的“预览下拉按钮”，点击后才展示命中商品列表
3. 强化左侧任务列表中的任务标题层级
4. 保持现有监控逻辑、接口与数据结构不变

## 非目标

- 不修改监控任务的后端接口
- 不修改命中商品的数据结构
- 不改变监控执行、启停、手动运行等逻辑
- 不新增复杂动画、抽屉、分页等额外交互

## 已确认的用户选择

- 命中商品预览入口位置：**右侧“最近命中”区域**
- 左侧需要高亮的标题位置：**任务列表中的任务名称**
- 目标：**不要默认直接展示全部命中商品**

## 方案选择

采用方案：**右侧最近命中区默认折叠 + 标题栏下拉按钮展开**。

不采用的方向：

- 每个左侧任务卡片单独内嵌预览：会让任务列表本身变重
- 默认显示少量命中摘要再“查看更多”：仍然属于默认暴露商品，不完全符合目标
- 抽屉式或复杂动画展开：超出本次必要范围

## 目标交互

### 1. 最近命中区域默认折叠

右侧详情区保留“最近命中”模块，但默认仅显示头部摘要，不直接渲染商品卡片网格。

头部摘要包含：

- 标题：`最近命中`
- 数量：当前 `activeHits.length`
- 刷新按钮
- 一个展开/收起按钮

默认状态：

- 按钮文案为 `展开预览`
- 商品卡片列表隐藏

展开状态：

- 按钮文案切为 `收起预览`
- 商品卡片列表显示

## 2. 展开状态行为

当用户点击“展开预览”后：

- 当前任务的命中商品列表显示
- 若 `activeHits` 为空且不在加载中，仍显示原有空状态
- 若点击“刷新”，只刷新数据，不强制改变折叠状态
  - 即：展开时刷新后仍保持展开
  - 折叠时刷新后仍保持折叠

## 3. 任务切换时的折叠策略

为保证行为稳定和可预期：

- 当切换左侧任务时，右侧“最近命中”预览**重置为折叠状态**
- 用户需要针对新任务主动点击“展开预览”查看命中商品

这样可以避免用户切换任务时右侧自动铺开大量商品，保持页面节奏一致。

## 左侧任务标题高亮设计

### 1. 层级目标

左侧任务列表卡片需形成更清晰的三层信息：

- 第一层：任务标题（最醒目）
- 第二层：关键词
- 第三层：状态、执行时间、命中数等辅助信息

### 2. 标题高亮要求

任务名称需要比当前更突出：

- 字号或字重上调
- 文本颜色更靠近主文本色
- 当前选中任务的标题进一步强化
- 与关键词、时间、命中数形成明显区分

### 3. 当前选中任务强化

对于 `activeTaskId === task.id` 的任务卡片：

- 标题颜色更亮或更高对比
- 可增加轻量的强调背景 / 左侧强调条 / 边框强调
- 但不使用过重的大面积高饱和背景，避免喧宾夺主

### 4. 次级信息弱化

任务关键词、执行时间、命中数、状态等内容保留，但相对标题弱化：

- 关键词仍清晰可读，但不与标题竞争
- 底部统计与时间信息保持次级文本色
- 状态标签继续保留，但不压过标题

## 实现思路

### 1. 新增本地折叠状态

在监控面板中新增一个仅前端使用的布尔状态，例如：

- `hitsExpanded`

用于控制当前右侧“最近命中”区域是否展开。

### 2. 在任务切换时重置折叠状态

监听 `activeTaskId` 变化时：

- 保持原有 `loadHits(taskId)` 行为
- 同时将 `hitsExpanded` 重置为 `false`

### 3. 调整最近命中头部结构

原有头部基础上新增一个显式切换按钮：

- 折叠时：`展开预览`
- 展开时：`收起预览`

头部仍保留：

- 标题
- 命中数量
- 刷新按钮

### 4. 商品列表增加条件渲染

当前的：

- `v-if="activeHits.length"` 直接显示商品网格

改为：

- 只有 `hitsExpanded` 为 `true` 时才进入列表显示逻辑
- 折叠时仅显示头部摘要，不显示商品网格和空状态卡片

### 5. 调整左侧任务卡片样式

优化类目包括：

- `.mp-task__name-row`
- `.mp-task strong`
- `.mp-task__keyword`
- `.mp-task__footer`
- `.mp-task--active`

让标题成为视觉第一焦点，其他信息退到辅助层。

## 视觉要求

### 右侧最近命中头部

- 按钮风格应轻量、明确
- 展开/收起文案一眼可懂
- 数量与刷新按钮继续保留
- 模块在折叠时仍显得完整，不像缺内容

### 左侧任务卡片

- 当前卡片和普通卡片有明确区分
- 标题强化但不破坏整体管理页风格
- 仍保持列表紧凑，不能因高亮导致卡片高度显著增加

## 错误与降级处理

- 若命中列表为空：
  - 折叠时仅显示数量为 `0`
  - 展开后显示空状态
- 若切换任务后请求命中列表中：
  - 折叠状态保持默认折叠
  - 用户可在加载完成后再手动展开
- 若刷新失败：
  - 沿用现有错误提示逻辑
  - 不额外改变展开/收起状态

## 测试策略

### 组件行为验证

至少覆盖：

1. 默认进入任务详情时，“最近命中”处于折叠状态
2. 点击“展开预览”后显示命中商品列表
3. 点击“收起预览”后隐藏命中商品列表
4. 切换任务后自动恢复折叠状态
5. 左侧任务标题高亮类在 active / non-active 状态下正确变化

### 手动验证

在真实页面确认：

- 进入监控页时，右侧不会直接铺满命中商品
- 点击按钮后可以正常看到命中商品
- 切换任务后不会自动继续展开
- 左侧任务标题更醒目，当前任务更容易识别

## 验收标准

满足以下条件即可认为完成：

1. “最近命中”默认折叠
2. 存在明确的“展开预览 / 收起预览”按钮
3. 只有展开时才显示命中商品
4. 切换任务后恢复折叠
5. 左侧任务标题层级明显高于关键词和底部信息
6. 当前选中任务标题有额外高亮效果
7. 现有监控功能逻辑不回归
