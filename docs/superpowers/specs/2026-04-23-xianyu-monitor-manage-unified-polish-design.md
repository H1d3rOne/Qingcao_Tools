# 咸鱼监控页与管理页统一中强度优化设计

## 背景

当前咸鱼工具已经完成监控、商品管理、自动发货与运行状态等核心功能，但页面在视觉语言与操作节奏上仍存在明显割裂：

- 监控页任务卡片、详情区、命中区层级还不够统一
- 管理页虽然已经有标签分区，但整体更像功能拼接，缺少完整的管理中心感
- 同类信息在不同页面的呈现方式不一致，导致扫读成本偏高
- 状态、摘要、主操作的视觉优先级还不够稳定

用户本轮希望：

- **监控页与管理页都优化**
- **视觉质感与操作效率同时提升**
- **不改接口**
- **不做桌面端 / 移动端专项适配**
- **接受中等强度改版，但不改变业务流本身**

## 目标

1. 将监控页与管理页统一为同一套“成熟工具页”视觉语言
2. 提升信息层级清晰度，降低扫读和理解成本
3. 提升核心操作的可发现性与顺手程度
4. 在不改接口的前提下，通过前端布局、样式、局部结构重排完成优化
5. 保持已有功能路径与主要交互逻辑稳定

## 非目标

- 不改任何后端接口
- 不改数据结构与业务模型
- 不新增复杂业务功能流
- 不重做路由结构
- 不进行专门的桌面端 / 移动端分化设计
- 不把页面改成纯表格后台或重装饰风格

## 已确认选择

### 范围约束

- 不改接口
- 只做前端布局 / 样式 / 交互细节优化

### 设计强度

- 采用 **中等强度改版**
- 允许做组件内部局部结构重排
- 不改动核心业务流程和接口调用方式

### 页面方向

- 监控页：**A · 稳重详情型**
- 管理页：**A · 分区运营型**

## 总体设计原则

### 1. 信息层级统一

两页统一按以下顺序组织信息：

1. 标题 / 当前状态 / 关键数字
2. 摘要说明 / 关键词 / 规则摘要
3. 时间、数量、补充信息
4. 操作按钮

目标是让用户进入任一区块后，都能用同样的阅读习惯快速判断：

- 这是什么
- 当前状态如何
- 是否需要进入处理
- 可以执行什么操作

### 2. 视觉语气统一

整体风格控制为：

- 更干净
- 更稳
- 更克制
- 更像成熟工具页

强调“信息优先、状态明确、主次清楚”，而不是营销感或重装饰感。

### 3. 操作优先级统一

所有页面中的操作都按主次分层：

- 主操作：强调按钮或主要入口
- 次操作：普通按钮 / text 按钮 / 次级入口
- 危险操作：单独强调，但不抢主操作视觉

### 4. 卡片与列表语言统一

监控页任务卡片、命中卡片，以及管理页商品卡片、规则区块、状态区块，统一采用相近的：

- 圆角
- 内边距
- 标题字重
- 次级信息颜色
- 状态标签密度
- hover / active 节奏

这样用户在不同页切换时不会产生“像两个系统”的割裂感。

## 监控页设计

### 1. 页面骨架

监控页保持双栏结构，但强化职责分工：

- 左侧：任务列表
- 右侧：当前任务详情 + 最近命中

左侧负责“选择”，右侧负责“理解与操作”。

### 2. 左侧任务列表

每个任务卡片统一为四层信息：

1. 标题 + 状态
2. 关键词
3. 可选筛选 / 条件摘要
4. 时间与命中数

#### 具体优化

- active 卡片继续高亮，但采用更稳的强调方式，不使用过重背景
- 标题作为最强视觉点，增强字重、字距、与状态的分离度
- 状态以小标签或稳定的状态文本承载，避免与标题竞争
- 关键词继续保留，但明显弱于标题
- 底部时间 / 命中数统一弱化并对齐
- 卡片间距、圆角、padding 统一，提升整列节奏

#### 解决的问题

- 卡片内容看着散
- 标题与次级信息层级不清
- active 状态识别不够稳定

### 3. 当前任务详情区

当前任务区改成更强的“摘要头部”：

包含：

- 任务名
- 核心规则摘要
- 最近执行时间 / 更新时间 / 已见商品数
- 状态标签
- 主操作按钮组：立即执行、启停、编辑、删除

#### 具体优化

- 标题、摘要、元信息按上下结构展开，而不是横向混排抢视觉
- 操作按钮组集中放置，减少用户搜索成本
- 状态类信息改为更稳定的 badge / 标签化表达
- 元信息改为统一的小字辅助区，不与操作按钮混在一起

#### 解决的问题

- 当前任务“能做什么”不够一眼明确
- 任务信息与操作入口分散
- 状态和摘要混在一起，不够清楚

### 4. 最近命中区

保留已经验证通过的默认折叠方案，并继续精修表现。

#### 保持不变的核心交互

- 默认折叠
- 点击“展开预览 / 收起预览”切换
- 带箭头方向提示
- 切换任务时自动重置为折叠

#### 本轮优化重点

- 最近命中标题区与控制区排版进一步稳定
- 展开按钮维持轻量，不抢“刷新”等主操作层级
- 命中商品卡片统一封面、标题、价格、时间、详情按钮的层级关系
- 标题与价格的视觉中心更清楚
- 空状态更克制，不显得断层或松散

#### 解决的问题

- 命中区展开后易显得松散
- 信息虽全，但层级和视觉节奏还不够成熟

## 管理页设计

### 1. 页面骨架

管理页采用“分区运营型”结构：

1. 顶部：管理头部 + 账号 / 汇总信息
2. 中部：三个主入口卡
   - 商品管理
   - 自动发货
   - 运行状态
3. 下部：当前激活模块主内容区

保留现有 tab 能力，但视觉上更像完整管理中心，而不是简单切页。

### 2. 管理页头部

当前头部升级为更有信息价值的概览区。

建议包含：

- 当前账号
- 商品数量
- 发货规则数量
- 运行中数量
- 异常数量或最近状态

#### 作用

- 用户进入管理页后先获得全局感知
- 为后续模块切换建立统一上下文
- 提升页面“管理中心”属性

### 3. 三个模块入口卡

保留当前三个入口，但统一提升为更成熟的模块卡：

- 图标区更稳定
- 标题更突出
- hint 从装饰文字变成真正有用的副说明
- active 态更自然，不依赖过重高亮
- 与监控页卡片语言保持一致

#### 目标

让用户在进入管理页时先完成“导航判断”，再进入具体模块。

### 4. 商品管理区

商品管理继续保留当前“封面 + 标题 + 价格 + 详情 + 操作”的核心结构，但优化为更统一、更适合高频浏览的列表卡片。

#### 具体优化

- 封面图区域尺寸、圆角、占比统一
- 标题与商品 ID 明确分层
- 价格继续高亮，但更简洁、稳定，不显得突兀
- 详情摘要限制可见长度，避免长文把列表撑乱
- 操作区重排：多数量发货开关与编辑 / 删除操作形成清晰主次
- 同步按钮区与统计区统一为同一种工具栏语言

#### 解决的问题

- 商品卡片有信息，但统一度还不够
- 封面、标题、价格、操作之间节奏不够稳
- 高亮价格虽然醒目，但整体排版还可继续收紧

### 5. 自动发货区

不改业务接口与配置能力，但统一其区块语言：

- 规则区标题与副说明统一
- 表单间距与分组更清楚
- 规则卡片的启用、禁用、异常状态表达统一
- 主操作与次操作分层更明显

#### 目标

让自动发货从“功能可用”变成“规则好读、状态好懂、修改顺手”。

### 6. 运行状态区

运行状态区统一为“状态摘要 + 明细”的结构。

#### 优化方向

- 顶部先展示当前运行状态或总体摘要
- 中下部展示最近记录 / 异常 / 说明
- 状态色和提示色与监控页、发货区统一
- 日志或记录区保持清晰，不做过度装饰

#### 目标

让用户快速判断：

- 是否正常运行
- 最近有没有异常
- 是否需要切换到发货规则或商品区处理

## 统一视觉与交互规则

### 1. 标题与副信息

- 标题维持强字重和较高可读性
- 副信息使用更稳定的次级色
- 时间 / 数量 / ID / 描述统一降级为辅助阅读层

### 2. 状态表达

统一使用少量状态语言：

- 运行中 / 已启用
- 已暂停 / 已关闭
- 异常 / 错误
- 空状态 / 暂无数据

颜色和标签密度在监控页与管理页之间保持一致。

### 3. 按钮主次

- 主操作保持清晰，但不过分饱和
- 次操作使用普通按钮或文字按钮
- 危险操作保持独立，避免与主操作并列抢视觉

### 4. 间距系统

统一收敛：

- 区块与区块之间的垂直间距
- 卡片内部上下节奏
- 标题与说明、说明与元信息、元信息与按钮的留白规律

### 5. 折叠与辅助区

适用于监控页命中区与管理页辅助摘要区：

- 默认只展示核心信息
- 次级内容按需展开或下沉到辅助区
- 避免把所有信息在初始视图一次性摊开

## 测试策略

### 组件测试

至少覆盖：

1. 监控页既有折叠 / 展开 / 切换任务逻辑不回归
2. 管理页模块切换不回归
3. 商品管理关键展示结构不回归
4. 如有新增稳定 class，可补最小结构断言

### 构建验证

- 运行相关 Vitest 测试
- 运行前端构建，确保模板与样式调整无编译问题

### 手动验证

重点确认：

- 监控页：左侧任务扫读是否更轻松，右侧详情是否更聚焦
- 最近命中折叠与展开是否自然
- 管理页：整体是否更像统一管理中心
- 商品管理：封面、标题、价格、操作是否更顺眼且更顺手
- 自动发货 / 运行状态是否明显更易读

## 验收标准

满足以下条件即可认为本轮设计达标：

1. 监控页与管理页视觉语言明显统一
2. 标题、摘要、状态、元信息、操作的主次更清楚
3. 监控页任务卡片和命中区更稳、更易扫读
4. 管理页更像完整管理中心，而不是零散功能区拼接
5. 商品管理区的封面、价格、标题、操作更协调
6. 不改接口、不改业务流
7. 相关测试与构建通过
