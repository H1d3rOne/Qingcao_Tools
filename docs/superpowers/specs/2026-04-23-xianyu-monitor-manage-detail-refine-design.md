# 咸鱼监控页与管理页第二轮细节精修设计

## 背景

在上一轮统一中强度优化完成后，咸鱼工具的监控页与管理页已经具备统一壳层、摘要区、模块入口和基础层级，但当前页面仍存在进一步精修空间：

- 监控页的重点信息已经比此前清楚，但“标题 / 状态 / 操作 / 命中摘要”的扫读节奏还能更顺
- 管理页三个子模块已统一到同一管理中心下，但模块内部的信息密度、按钮主次、次信息弱化方式还不够稳定
- 商品管理、自动发货、运行状态三个工作区虽然功能完整，但切换时仍有“同一系统下不同页面”的轻微割裂感
- 当前页面已经进入“做质感”的阶段，需要在不改接口、不改业务流的前提下，把间距、状态色、按钮层级和阅读节奏继续统一

用户本轮已明确：

- 视觉方向采用 **平衡偏克制**
- 信息密度采用 **平衡适中**
- 接受 **轻度结构重排**，但不改接口、不新增功能
- 监控页和管理页 **两边都要继续优化**

## 目标

1. 在不改接口与业务能力的前提下，继续提升监控页与管理页的扫读效率
2. 统一摘要区、操作区、主内容区、次信息区的视觉语言
3. 让标题、价格、状态、命中数、执行结果等核心信息更容易被一眼识别
4. 让商品管理、自动发货、运行状态三个子模块拥有更一致的工作台节奏
5. 保持已有可用逻辑、交互与测试边界稳定

## 非目标

- 不修改后端接口、参数结构、返回结构
- 不新增业务功能、过滤能力或全新交互链路
- 不改路由结构与页面入口
- 不做桌面端 / 移动端专项分支设计
- 不把页面改成重装饰、重营销或强色块风格
- 不重写已通过验证的命中预览折叠逻辑与管理 tab 主流程

## 已确认方向

### 设计风格

- **平衡偏克制**：重点信息清楚，但整体不做过亮、过满、过炸的强调
- **平衡适中**：不追求极致紧凑，也不做大留白，保持工作台效率与阅读舒适度平衡

### 结构策略

- 允许做 **轻度结构重排**
- 仅在现有组件内部重组摘要、操作、主体、辅助内容的层级
- 不改变数据来源、接口调用和业务行为

### 总体方案

采用 **信息分层型** 方案：

- 监控页与管理页统一按“摘要区 → 操作区 → 主内容区 → 次信息区”组织
- 核心信息上浮，次要说明下沉或弱化
- 把高频浏览路径做得更顺，把长文本和补充信息控制在不抢主视线的位置

## 总体设计原则

### 1. 先扫重点，再读细节

每个区块都优先暴露四类信息：

1. 这是什么（标题 / 模块名 / 规则名 / 商品名）
2. 当前状态如何（启用、停用、成功、失败、同步状态）
3. 值不值得处理（命中数、价格、异常、最近执行）
4. 能做什么（运行、启停、编辑、删除、查看详情）

补充说明、长摘要、技术性字段、辅助提示统一延后。

### 2. 状态色存在但不过度喧宾夺主

- 绿色 / 蓝色用于正向状态与主路径提示
- 橙色用于观察中、提醒类信息
- 红色仅用于失败、删除、异常，不大面积铺陈
- 价格高亮保留，但控制饱和度与面积，让其“醒目但不刺眼”

### 3. 按钮层级明确且跨模块统一

所有主要区块统一为三层：

- **主操作**：立即执行、启停、同步等最常用动作
- **次操作**：编辑、查看、复制文本等补充动作
- **危险操作**：删除等破坏性动作，单独处理但不抢主操作视觉

### 4. 主区负责处理，辅助区负责解释

- 主区承载高频内容：列表、卡片、执行记录、规则主体
- 辅助区承载说明、帮助、补充信息、空状态引导
- 不再让说明性内容混入主操作与主列表中心位置

### 5. 统一工作台节奏

监控页与管理页虽然职责不同，但应共享同一种阅读节奏：

- 先看摘要
- 再看当前焦点与状态
- 再做操作
- 最后查看展开内容与补充解释

## 监控页设计

## 1. 页面目标

把当前监控详情从“信息堆叠”继续精修为“任务工作台”：用户先看任务身份、运行状态与最近结果，再决定是否展开命中商品或执行操作。

## 2. 顶部摘要区重排

现有摘要头保留，但收敛为更清晰的两层：

### 第一层：任务身份层

包含：

- 任务标题
- 启用 / 停用状态
- 主操作按钮组

目标是让用户一眼知道当前正在看哪个任务、是否在运行、接下来可以做什么。

### 第二层：任务摘要层

包含：

- 关键词
- 轮询频率
- 价格区间
- 命中数量
- 最近执行时间

这层采用统一的元信息 / pill / 辅助标签风格，不再与标题抢同一级视觉。

## 3. 任务标题与关键词层级强化

- 任务标题继续提升字重与对比，成为详情区第一视觉锚点
- 关键词保留高亮，但降一级，作为“检索标签”而不是标题替代物
- 筛选说明、附加条件、补充字段统一弱化，避免与标题竞争

## 4. 按钮主次统一

监控详情区按钮统一分为：

- 主操作：运行 / 启停
- 次操作：编辑
- 危险操作：删除

按钮排列上强调稳定与易扫读，不让所有按钮看起来同样重要。

## 5. 命中商品区优化

保持当前已验证通过的“默认折叠 + 点击展开 + 切换任务重置折叠”逻辑不变，继续精修为：

### 默认展示预览条

只展示：

- 命中数量
- 最近一条命中摘要
- 展开按钮

### 展开后展示轻量条目列表

命中商品不再在收起状态下占据太多空间；展开后每条命中项优先突出：

- 商品标题
- 价格
- 时间
- 查看详情入口

封面、补充文案、附加字段不抢任务主体。

## 6. 左侧任务列表联动优化

不改变数据和入口，但会继续增强：

- 当前任务高亮识别
- 列表项标题与状态分离
- 最近命中、最近执行时间作为底部辅助信息
- 切换任务时右侧命中预览自然回收

## 管理页统一设计

## 1. 页面目标

让管理页真正形成统一管理工作台，而不是“头部 + tab + 三个风格略不同的子页面”。

三个模块都统一到同样的工作节奏：

- 摘要条
- 工具栏
- 主工作区
- 辅助说明区

## 2. 管理中心壳层继续收紧

### 顶部概览区

概览区继续保留，但精修信息层级：

- 当前账号
- 模块数量
- 默认入口
- 当前焦点

通过更稳的排版、字重和说明文案，让概览区承担“进入页面后的第一眼判断”，而不是仅作装饰统计。

### 模块入口卡

商品管理、自动发货、运行状态三张入口卡继续统一：

- 图标块尺寸、色块重量、hover 与 active 节奏一致
- 标题是主视觉点
- hint 是功能摘要，不是陪衬装饰
- active 状态强调当前焦点，但避免大面积重色块压迫感

## 商品管理设计

## 1. 目标

把商品管理打磨成“高频浏览 + 快速处理”的主工作区，突出商品主体、价格、状态与更新时间，降低辅助信息干扰。

## 2. 顶部摘要与工具栏

商品管理区顶部继续承担当前工作区状态：

- 商品数量
- 最近同步状态
- 当前搜索 / 筛选感知
- 主操作入口

工具栏与统计区视觉统一，形成同一种“工作区控制条”语言。

## 3. 商品列表信息层级

每个商品条目优先突出：

- 封面图
- 标题
- 价格（高亮）
- 状态标签
- 更新时间

统一弱化：

- 商品 ID
- 长摘要
- 扩展字段
- 非关键说明

## 4. 价格高亮策略

价格继续高亮，但控制表现方式：

- 颜色更凝练
- 与标题形成稳定上下层级
- 不通过过大字号或过强饱和度破坏整体平衡

目标是“扫一眼就看到价格”，但不会让整个列表只剩下价格在发光。

## 5. 主区与辅助区职责明确

- 主区：商品列表、封面、标题、价格、状态、操作
- 辅助区：说明、提示、空状态、选中商品的补充信息

这样主区保持紧凑高频，辅助区承接解释性内容。

## 自动发货设计

## 1. 目标

让自动发货规则从“信息都在卡片里”进一步变成“规则可快速扫读、状态可快速判断、操作入口稳定”的规则工作区。

## 2. 规则卡层级重排

每张规则卡统一为四层：

1. 规则标题区
2. 状态 / 命中条件摘要
3. 内容主体
4. 底部操作区

## 3. 首屏突出可判断信息

用户无需读完整文本，就能先看出：

- 规则是否启用
- 针对什么商品 / 关键词
- 发货内容类型
- 最近执行是否正常

## 4. 长文本与说明弱化

发货文本、详细条件、补充说明采用更克制的方式展示，优先把结论性内容放在前面；避免整张卡片被长文本撑散。

## 运行状态设计

## 1. 目标

把运行状态区做成“可扫读的执行记录区”，让用户先知道总体运行是否正常，再看单条异常。

## 2. 顶部摘要

优先展示：

- 最近执行总数
- 成功 / 失败分布
- 最近一次执行时间
- 当前观察重点

## 3. 执行记录列表

每条记录优先突出：

- 执行结果
- 关联规则 / 商品
- 时间
- 关键原因

payload、补充字段、次要元信息统一弱化，避免一屏信息过吵。

## 4. 异常态表达

失败与异常项会更容易扫到，但仍遵循“平衡偏克制”的基调：

- 重点在于识别效率
- 不靠满屏红色制造紧张感

## 测试与验证边界

## 明确保留的行为

本轮不改变以下已验证可用的行为：

- 监控任务切换逻辑
- 命中商品预览展开 / 收起逻辑
- 管理页 tab 切换逻辑
- 商品封面展示逻辑
- 当前已接通的商品管理、自动发货、运行状态接口调用方式

## 验证重点

### 1. 监控页

- 任务切换是否正常
- 命中商品预览是否正常展开 / 收起
- 标题、状态、命中摘要是否正常显示
- 主次按钮仍可用且层级清楚

### 2. 商品管理

- 商品封面、标题、价格、状态、更新时间显示正常
- 工具栏、主区、辅助区排版稳定
- 空状态、加载态不破版

### 3. 自动发货

- 规则卡摘要、主体、底部操作区显示正常
- 启用状态、文本内容、按钮入口不受影响

### 4. 运行状态

- 执行记录正常渲染
- 成功 / 失败状态可读性提升
- 摘要区与辅助说明区显示稳定

### 5. 基础回归

- 相关组件测试继续通过
- `vite build` 继续通过
- 必要时继续以本地 mock 方式做页面级验证

## 预期结果

本轮完成后，页面应体现出以下结果：

- 监控页更像任务工作台，重点信息更先被看到
- 管理页三个子模块切换时，明显属于同一个系统
- 价格、状态、执行结果等关键点更容易扫到
- 视觉更整洁、主次更明确，但整体仍保持克制
- 接口、功能边界、已有交互主流程保持不变
